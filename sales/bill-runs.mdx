An invoice run issues invoices for every charge in a period that is not invoiced yet, in one batch. Owners and admins run one by hand or on a schedule, so every member has a dated, numbered invoice without anyone creating them one by one. Invoice runs were called **bill runs** until October 2026.

<Note>
  An invoice run takes no payments. It doesn't charge anybody, email anything,
  or retry a failed payment - it issues invoice documents and stops. Membership
  renewals are charged by the renewal engine (see [Membership
  billing](/sales/membership-billing)), and you collect anything else from
  [Charges](/sales/charges) or an invoice's payment link.
</Note>

## When to use it

Use an invoice run when your members or their companies need a formal invoice for what they were charged, and you don't want to issue each one by hand. You choose the period and filters, preview the result, and anything already invoiced is skipped.

Typical uses:

- **Monthly invoices for everyone** - a yoga studio schedules an invoice run for the 1st of each month, so every member has an invoice for last month's charges, while the renewal engine does the charging.
- **Invoices for one plan only** - a climbing gym invoices its youth-team memberships for a school's accounts office, filtered to the youth plan.
- **A catch-up run** - a scheduled run was stopped for a month, so you run one by hand for that period. Charges already invoiced are skipped.

To bill a company for the people it pays for, issue an invoice to the company's account from [Invoices](/sales/invoices) instead.

## How it works

### What gets invoiced

A charge is included when all of these hold:

- Its date falls inside the period.
- It is not on an invoice yet, and not on an outstanding pro-forma.
- It is not void.
- It is a booking, a membership, a membership renewal, a signup fee, or an early cancellation charge. Booking cancellation reversals are left out, because they are settled, not owed.

Charges that are already paid are still included as long as they aren't invoiced yet. Their invoice simply opens as paid.

### How charges are grouped

Each customer gets one invoice for all their charges in the period. If you sell through more than one [billing entity](/settings/billing-entities), a customer who bought from two of your companies gets one invoice from each, because one invoice always comes from one company.

<Note>
  An organization can also be set to issue a single invoice per company for
  every charge in the run, addressed to the first customer, for billing one
  corporate payer. This can't be changed from the admin; the default is one
  invoice per customer.
</Note>

### What each invoice gets

- A number from the issuing company's invoice numbering template (see [Document numbering](/sales/invoices#document-numbering)).
- An invoice date of the day the run executed, on your organization's clock.
- A due date 30 days after the invoice date.
- One line per charge, linked back to it.
- A status worked out from those charges: paid, partially paid, pending, or overdue.

Each included charge is then marked as invoiced, so no later run picks it up again.

## The invoice runs list

Go to **Sales** > **Finance** > **Invoice Runs** (`/billing/invoices/bill-runs`). The list shows every run with its **Invoice Run Name**, **Period Start**, **Period End**, **Invoices**, **Total Amount**, **Status**, and **Created At**. Click a run (or **View**) to open its **Invoice Run Details**: its name, period, status, total, and invoice count, followed by every invoice it created.

## Running an invoice run by hand

1. Go to **Sales** > **Finance** > **Invoice Runs** and click **Invoice Run**. The same button sits in the **Invoices** tab's header.
2. Give the run an **Invoice Run Name**. It defaults to the month followed by "Invoices", for example "March 2026 Invoices".
3. Pick a **Period Start** and **Period End**.
4. Optionally narrow it under **Filters (Optional)**: **Charge Types**, **Min Amount** and **Max Amount**, **Contacts**, and **Plans**.
5. Click **Preview** to see exactly which charges will be invoiced: the number of **Charges**, **Contacts**, the **Total Amount**, how many **Invoices** it makes, the charge types, and the full list of charges. **Clear Preview** starts again.
6. Click **Confirm** to issue the invoices. You land on the run's details page.

### Per-field guide

| Field                             | When to use it                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Invoice Run Name**              | Label the run so you can find it later, for example "March 2026 memberships".                              |
| **Period Start** / **Period End** | Bound which charge dates are swept. Widen it to catch a missed period; narrow it to invoice a single week. |
| **Charge Types**                  | Invoice only some charges, for example membership renewals but not one-off bookings.                       |
| **Contacts**                      | Invoice a specific set of members.                                                                         |
| **Plans**                         | Only memberships on the chosen plans.                                                                      |
| **Min Amount** / **Max Amount**   | Leave out very small or unusually large charges.                                                           |

## Automated Invoicing

To run invoice runs on a schedule, go to **Settings** > **Billing** > **Automated Invoicing** (`/settings/billing/automated`) and click **New scheduled invoice run**. In **Create Invoice Run Schedule**, set:

- **Schedule Name** and **Description** (both required).
- **Frequency** - **Daily**, **Weekly**, or **Monthly** - with a **Time**, and a **Day of Week** or **Day of Month** where it applies. The list shows the schedule in plain words, for example "Day 1 of every month at 09:00".
- **Filters (Optional)** - the same filters as a run by hand.

Each scheduled run covers the first day of last month through the last day of this month, on your organization's clock. That way a run on the 1st still invoices the month that just ended. Overlapping periods never invoice anything twice, because charges already invoiced are skipped.

The schedule list shows each schedule's **Name**, **Description**, **Schedule**, **Filters**, **Next run**, and **Status**. Each row offers **Edit**, **Delete** (its automated runs stop), and, on an active schedule, **Run Now**. **Run Now** asks "Run the invoice run now?" and then takes you to the invoices it issued. Runs from a schedule are named `Automated: <schedule name>`, and runs started with **Run Now** `Manual run: <schedule name>`, so you can tell them apart in the list.

A scheduled run happens in the background and emails no members. Admins and managers get a billing [notification](/settings/notifications) when it finishes, with how many invoices it issued and their total, or why it failed. Its invoices appear in the **Invoice Runs** list.

Creating, editing, and deleting schedules needs the **billing.manage.organization** permission.

## Deleting an invoice run

There is no button to delete an invoice run. It can be deleted through the API only, with the **billing.manage.organization** permission. Deleting a run removes the run itself and keeps its invoices, which simply no longer point at a run. Their charges stay invoiced. To make those charges invoiceable again, delete the invoices too.

## Worked examples

**Yoga studio - monthly invoices.** Members on monthly plans are charged by the renewal engine on their renewal day. Separately, you schedule a monthly invoice run for the 1st at 09:00, so every member has an invoice for last month. The run charges nobody - it only puts the charges already raised onto invoices.

**Climbing gym - one plan for a school.** A local school pays for its students' youth-team memberships and needs invoices for its accounts office. Run an invoice run for the month, filtered under **Plans** to the youth-team plan, preview it to confirm the count, then **Confirm**. Each student's payer gets an invoice for their own charges, ready to download and send from [Invoices](/sales/invoices).

**Padel gym - catch-up run.** Your scheduled run was stopped for a month while you changed accountants. Run one by hand with that month as the period, preview it, and confirm. Anything already invoiced is skipped.

## Tips & best practices

- **Invoice runs issue invoices; renewals take the money.** If members need to be charged automatically, the lever is auto-renew on the plan and a saved card - see [Membership billing](/sales/membership-billing).
- **Always preview before you confirm.** Once you confirm, invoices are issued and numbered, and the charges are marked invoiced.
- **Filter scheduled runs** so they sweep only what you intend. An unfiltered run picks up every invoiceable charge in the period.
- **Set your numbering template first.** Every invoice a run issues takes the next number in the company's series.

## Troubleshooting

| Symptom                                                  | Cause                                                                                                      | Fix                                                                                                                                                                 |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An invoice run confirmed but no money was collected      | Invoice runs never take payments.                                                                          | Collect from [Charges](/sales/charges) or with an invoice's payment link; renewals are charged automatically - see [Membership billing](/sales/membership-billing). |
| A charge you expected isn't in the preview               | It is void, already invoiced, on an outstanding pro-forma, outside the period, or not an invoiceable type. | Check its status and date. To invoice it again, delete the invoice that holds it.                                                                                   |
| A member got two invoices from one run                   | They bought from two of your billing entities.                                                             | Expected: one invoice always comes from one company.                                                                                                                |
| Deleting a run didn't make its charges invoiceable again | Deleting a run keeps its invoices, which still hold the charges.                                           | Delete those invoices too.                                                                                                                                          |
| A scheduled run invoiced last month's charges as well    | Each scheduled run covers last month and this month.                                                       | Expected. Nothing is invoiced twice.                                                                                                                                |
